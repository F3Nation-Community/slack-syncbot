# AGENTS — SyncBot

This file is the primary instruction set for AI coding agents (Cursor, GitHub Copilot, Codex, Claude via `CLAUDE.md`).

## Project snapshot

SyncBot is a **Slack app** that syncs messages, threads, edits, deletes, reactions, and media across **multiple Slack workspaces** (and optional **federation** between instances). The runtime is **Python 3.12+**, **Poetry** for dependencies, **SQLAlchemy** + **Alembic** for the database, and **Slack Bolt**.

Deployments supported in-repo: **AWS** (Lambda + SAM) and **GCP** (Cloud Run + Terraform). Application code under `syncbot/` must stay **cloud‑neutral**; provider-specific pieces live only under `infra/aws/`, `infra/gcp/`, and deploy workflows.

## Repo map (short)

- `syncbot/` — application (`app.py`, handlers, db, federation).
- `syncbot/db/alembic/` — schema migrations.
- `tests/`, `infra/aws/tests/`, `infra/gcp/tests/` — pytest suites.
- `infra/aws/`, `infra/gcp/` — SAM/Terraform, bootstrap, CI deploy helpers.
- `docs/` — architecture, deploy, infra contract, user guide.
- `.github/workflows/` — CI, deploy, release automation.

See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for Dev Container / Docker Compose / native setup.

## Hard rules (guardrails)

1. **Provider-neutral `syncbot/`** — do not add `boto3`, `google.cloud`, or other cloud SDK imports under `syncbot/`. Use `infra/<provider>/` and workflows for provider code. This is also enforced in CI (`forbidden-imports` job).
2. **Version & changelog** — do not bump `pyproject.toml`’s `version` or `syncbot/constants.py` `__version__`, or add a `## [X.Y.Z]` heading in a feature PR. Releases on `main` are automated with **python-semantic-release**. Put Keep a Changelog notes (**Added** / **Changed** / **Fixed**, **[1.2.0](CHANGELOG.md)** length) under `## [Unreleased]` below `<!-- version list -->`; the release job retitles that heading to the version and date and copies that section onto the GitHub Release. A database change, environment change, or operator step is a **NOTICE** or **REQUIRED** bullet at the top of **Changed**, as described under **Docs voice**. If Unreleased is missing, PSR drafts from `feat` / `fix` / `perf` subjects. Polishing an already-released heading is OK. See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) and [CONTRIBUTING.md](CONTRIBUTING.md).
3. **Requirements files** — do not edit `syncbot/requirements.txt` by hand. Change dependencies in `pyproject.toml` and run the pre-commit `sync-requirements` hook or `poetry export` as in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
4. **Secrets** — never commit real `.env`, `.env.deploy.*` (only `*.example` templates), private keys, or large artifacts. Do not commit `.aws-sam/build` output.
5. **Deployment branches** — on a **fork**, do not push to `test` or `prod` as a casual step; those branches deploy. Canonical releases run only on **F3Nation-Community/slack-syncbot** `main` (see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)). Forks pull `main` and promote to `test`/`prod` themselves. AWS lives under `infra/aws/` and GCP under `infra/gcp/`. `FEDERATION_HTTP_MAX_MB` is injected there (`30` on Cloud Run, `4` on Lambda). Do not copy those numbers into `syncbot/`. `GET /health` and `GET /ready` are long-running only. A Lambda Function URL answers 404 to a stray GET.
6. **Conventional Commits** — PR titles and commit subjects are one short imperative line (`fix: …`, about 72 characters). Skip the body unless you need `BREAKING CHANGE:` or a single clause that will not fit. See [CONTRIBUTING.md](CONTRIBUTING.md).
7. **Docs** — if behavior, env vars, or deploy steps change, update the relevant `docs/*.md` (and [docs/INFRA_CONTRACT.md](docs/INFRA_CONTRACT.md) if the runtime contract changes). Follow **Docs voice** below. The **Message Sync Flow** walkthrough in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) links to functions by `#L` line; when you move, rename, or split those functions, retarget every link. Keep the mermaid same-instance / cross-instance, and infra-agnostic (Slack → SyncBot → Slack).
8. **Plan files** — write working plans only under **`.plans/`** at the repo root (gitignored). Never put them under `docs/` even if ignored — that looks like operator docs. Never commit plan files. `docs/PLAN_*.md` and `PLAN_*.md` stay gitignored as a safety net for leftovers.

## Docs voice

Operator-facing docs (README, `docs/*.md`, `.env*.example`, `infra/gcp/example.tfvars`) should read like a helpful teammate: friendly and explanatory, not clipped or telegraphic. Write full sentences (do not drop “the” or “a” to shorten a line). Prefer a short paragraph over a dense jargon pile.

Stage is only **`test`** or **`prod`**. Do not use `YOURSTAGE` as if the name were arbitrary. Show the real values (`--env test`, `slack-manifest_test.json`, `syncbot_test`) and mention `prod` as the other choice. Keep `YOUR_*` for values that really vary (region, host, username).

**Changelog / GitHub Release notes** follow Keep a Changelog and **[1.2.0](CHANGELOG.md)** length: one short line per bullet, not the operator-docs paragraph style. Do not write an operator-guide paragraph into the changelog.

When operators should know about a database or environment change, or still have to act, put one short bullet first under `### Changed` in `## [Unreleased]`. Keep the same length. Leave the headings as **Added** / **Changed** / **Fixed**. The release job copies that block onto the GitHub Release. A later edit of a published section does not change the Release page, so update that Release body to the same text when you polish one.

**NOTICE** means they should know before going on. Use it for a database change, and for an environment name that still loads or that the app ignores because it already has the replacement.

- `NOTICE: Database migration in this release;` when an Alembic revision rewrites or drops stored data. Name what changes. Deploy runs a new table or column on its own, so that revision stays a normal bullet.
- `NOTICE: Environment change in this release;` when an old name still loads, or the app ignores a leftover name and already has the replacement. Name the variable and what happens.

**REQUIRED** means a person has to act. Use it when deploy or a feature fails until they do.

- `REQUIRED: Slack manifest needs to be updated;` when bot scopes, user scopes, bot events, or the Slack request, interactivity, or redirect URLs change. Name the change. Say to reinstall when a new bot scope has to be on the token.
- `REQUIRED: Environment change in this release;` when a value has to change, or a feature stays off until env or Settings is updated. Name the variable and the action.
- `REQUIRED:` with a short description for another operator step, such as re-running bootstrap or stopping because the stack still has RDS.

**Example names** — Use generic fixtures, not operator screenshots or community-specific names. Workspaces: `Workspace A`, `Workspace B`. Channels: `#general`, `#announcements`. People: `Ada Lovelace`. Connection labels: `Partner Org` (not a workspace name). A missing workspace name is `Workspace`. URLs: `https://ws-a.example`, `https://peer.example`. Do not copy names from screenshots. Prefer "set up" when you mean the action. In operator docs the database name is `DATABASE_BACKEND`, not a deploy alias.

## Common pitfalls

- **Slack Free.** Target audience is Free workspaces. When reading Slack API docs, keep only Free or all-plan facts. Ignore Slack Connect, Enterprise Grid, remote-files, paid retention, and Audit Logs. `hidden_by_limit` and `storage_limit_reached` are Free. Slack's per-file limit is 1 GB; do not invent a smaller app cap. Do not add `files.info` for `check_file_info`.
- **Bot identity is per workspace.** Never cache `auth.test` under a process-wide key. A warm process handles many workspaces; reusing workspace A's bot member ID on B makes `conversations.invite` fail with `user_not_found` and can skip `leave_channel_without_sync`. Prefer Bolt's request-scoped `context["bot_user_id"]`, and cache `auth.test` keyed by bot token.
- **Settings are modal-only.** Instance fields (`federation_enabled`, `soft_delete_retention_days`, `workspace_block_list`) use `instance_settings` on the primary workspace. Workspace fields (`allow_private_channels(team_id)`, extra managers) use `workspace_settings`. Leftover env (`ALLOW_PRIVATE_CHANNELS`, `SOFT_DELETE_RETENTION_DAYS`, `SYNCBOT_FEDERATION_ENABLED`, `REQUIRE_ADMIN`) is ignored and warned. `PRIMARY_WORKSPACE`, `ENABLE_DB_RESET`, and `ENABLE_UNSIGNED_IMPORT` stay env. The Workspace Block List is Team IDs (`T` + alphanumeric). Ack rejects the primary Workspace and a group Owner. Newly added installed IDs call `apps.uninstall` then `uninstall_workspace`. OAuth `save` / `save_bot` refuse a blocked team (do not persist). `convert_workspace_to_local` is refused while listed. Removing an ID does not auto-reinstall.
- **Federation on/off** is `helpers.federation_enabled()` at call time (Settings DB), not an import-time constant. Do not freeze at HTTP listen. Default off on a new install.
- **Private membership.** Write `Sync`/`SyncChannel` then invite. Public = bot `conversations.join`; private = `conversations.invite` with the acting user's `xoxp` only, gated by `allow_private_channels(team_id)`. Failed invite rolls back and DMs. Leave when the Channel is not in a Sync stays (`leave_channel_without_sync`). Treat `already_in_channel` / `cant_invite_self` / `method_post_only` as success. Invite only `U…` member IDs, never `B…`. Resume passes Bolt `context` only when the channel's workspace is this request's workspace. Use `lookup_channel_name` for Channel names (the bot cannot see a private Channel it has not joined).
- **Native `conversations_select`.** Do not rebuild channel pickers from `conversations.list` (~100 cap). The filter is advisory; validate on submit.
- **Helpers import submodules only.** Never `import helpers` inside `helpers/*.py` — `helpers/__init__.py` circular-imports at process start. See [`syncbot/helpers/sync_cleanup.py`](syncbot/helpers/sync_cleanup.py).
- **`is_workspace_admin` vs `is_workspace_manager`.** Admins open Settings, Backup, Reset, and External Connections (primary only). Managers configure groups and syncs. Authorize and Refresh stay for everyone.
- **Direct reactions** use `get_user_token(target_team_id, mapped_user_id)`, never the event team. Never send `xoxp` on federation envelopes. Do not store reverse-map results as target `xoxp` lookup keys.
- **User-token echo.** Native `reaction_added` is the mapped person, not the bot. After user-token add/remove, `remember_pending_event` with the `reaction_added` / `reaction_removed` kind; the matching event's `take_pending_event` runs **inside** `run_claimed` (not `processed_events`; consume-once). The kind is Slack's event type, and the row is the target Channel, `item.ts`, and the emoji name, in their own columns. File shares posted as the mapped person have no `bot_id`: remember Slack file ids from `files.getUploadURLExternal` **before** `files.completeUploadExternal` shares into the Channel; inbound events **check** `FILE_ECHO` and `MESSAGE_ECHO` (`check_pending_event`; do not take) so `file_share` and a later `message_changed` skip. Remember the share message ts, never the thread parent. Copy PostMeta is written when the target post lands. Inbound *creates* of that copy are skipped by echo and `post_meta_exists_for_channel_ts`. Reactions, thread replies, edits, and deletes on a publishing Channel still originate from the shared `post_id`; echo skips the apply SyncBot just wrote.
- **`pending_events` holds addresses only.** Every row is a pending event, and its `kind` says which (`helpers/pending_events.py`). Use `remember_pending_event`, `check_pending_event`, and `take_pending_event` for every kind; `_COLUMNS` lists each kind's columns and refuses a call with a missing, empty, or unused one. Do not add per-kind wrappers or a second class for a row (`PendingFileShare` stays: it is the copy's PostMeta, not the row). Do not call these rows notes or follow-ups. A row holds ids, timestamps, and a reaction's name, which is its address (Slack has no reaction id, and reading reactions again cannot tell the person's from the ones SyncBot placed as them). Anything Slack can give back from an address (text, blocks, files, attachments, names, avatars) is read again, never stored, even for a replay. Each value has its own typed column, one meaning each: `target_*` is where SyncBot wrote or will write, `source_*` is where a person acted. Never add a packed, free-form, or content column (`detail`, `content`, `payload`, a fingerprint string). `tests/test_pending_events.py` pins the columns; adding one means editing that test. Only rows from the last 10 minutes count: every check and take skips older ones, so correctness never waits on cleanup. A handler deletes only the rows it takes, each with one atomic `DELETE`; `purge_expired_pending_events` sweeps the rest from `refresh_instance` (keep-warm, `/health`, `/ready`). Never purge in a handler. Backups omit the table.
- **`post_meta.ts` is DECIMAL(16, 6).** Never `float(ts)` to persist or compare. A current Slack ts does not fit in a float, so reactions and thread replies miss older rows. Use `post_meta_ts(ts)` for that column (write and `==`), and for the `pending_events` ts columns. `slack_message_ts` is the string form for Slack API kwargs (`str(Decimal)` drops trailing zeros). Both live in `helpers/slack_ts.py`. Do not add another converter.
- **Hybrid thread.** Target `invalid_name` never threads. Probe target emoji names with the bot token **only** when about to post a Hybrid thread in **another workspace** (no target `xoxp`, or that token hit `_NO_AUTHORIZE_ERRORS`). Same-workspace Hybrid skips the probe (shared emoji catalog). Federation inbound is a different Slack workspace — probe it the same as same-instance cross-workspace. Origin having the emoji does not mean the target has it. Direct-only and a successful native add never probe. Off is a no-op for add and remove. Inbound reaction apply is last-write-wins on envelope `event_ts`. Do not use `emoji.list`; the target bot `reactions_add`/`reactions_remove` probe is the current method. Hybrid notices `chat.postMessage` with the Slack thread **root** (`conversations.replies` `thread_ts` when it differs from the reacted ts; channel history does not return replies). Unreact `chat.delete`s target Hybrid notices (children first); never reuse the parent message `post_id`. Off does not delete leftover notices. A target user deleting a notice is a local tombstone only — no origin `reactions_remove`, no other target rows. Same-channel `apply_reaction_to_target` is always skip. Pre-1.4.1 uuid notices: leftover thread scan deletes only bot posts whose text is `reacted with :emoji:`; never a human reply that merely mentions the emoji.
- **Token encryption at rest.** Bot tokens live in Bolt `slack_bots` (`helpers.workspace.get_bot_token`); user tokens in `slack_installations` (via `EncryptedSQLAlchemyInstallationStore`). Never compare two Fernet ciphertexts for equality — decrypt stored token and compare plaintext when refreshing. Federation file-part payloads use the same `DATA_ENCRYPTION_KEY` (`encrypt_bytes` / `decrypt_bytes`). `federation_file_parts` is an in-flight mailbox (TTL ~5 minutes); omit it from backup and migration export. `offer_have` uses stored `part_total` (the sender's part count), not `func.length(payload)` (ciphertext is not plaintext size) and not `max(part_index)+1` (part 0 of N is not a complete file).
- **`get_workspace_record` creates, restores, or refreshes a Workspace only when `context["team_id"]` is that Workspace.** Bolt's client and bot token belong to that install. Callers that build their own body pass `{"team_id": team_id}`. `get_team_id_from_body` stays the Workspace the event is about.
- **Home hash is per user** (`home_tab_hash:{team_id}:{user_id}`). Prefix delete on restore still works. Hash payload must include manager/admin role, extra-manager lists, group names, member roles, sync titles, each stub member's workspace name, each Channel's `is_private`, whether this Workspace allows private Channels, the viewer's sorted private Channel ids (`None` when not loaded, `()` for an empty answer), External Connection fingerprint (peers, allowlists, remote stubs, waiting codes), and whether `authorize_url` has an origin in this process, so a Home built before a verified Slack request is rebuilt on the next open. `app_home_opened` re-publishes the cached blocks when that hash matches. Refresh publishes this user's tab when the hash changed and does not pulse External Connections. `/health`, `/ready`, and keep-warm pulse allowlists and send the snapshot one slice at a time. Post-deploy `views.publish` uses remembered Home viewers in `workspace_settings` (plus extra managers); do not crawl `users.list`. Keep-warm must not republish Home.
- **Home push is the acting user plus hash invalidation.** Do not call `get_admin_ids` / `users.list` to fan out Home. Others refresh on `app_home_opened`. Inbound federation is invalidate-only (no `views.publish`). A `/teams` drop soft-deletes the workspace (its rows become `uninstalled`). Home **Refresh** publishes this user's tab only when the hash changed. An unchanged hash does nothing.
- **User Mapping is a modal.** The ack opens Loading and the work phase fills it from DB mappings only. Never seed, map, or crawl before that fill. **Auto Map Now** updates the open modal via `view_id` (close-only wait view, then the list and last-run line). Never `views.publish` Home for mapping. Auto Map Now from `user_directory.email` with `allow_slack_email_lookup=False` on the button (no source `users.info` either); do not crawl `users.list` on open, Refresh List, Auto Map Now, or group join. **On-the-fly author map** (`ensure_mapped_target_user_id`) is one person, email only (directory then one target `lookupByEmail`); not a full Auto Map Now.
- **Button modals open in the ack.** `action_ack` opens a close-only Loading view for `MODAL_OPEN_ACTIONS` (`views.push` only for Edit Mapping). The work phase fills it with `views.update` by `external_id`. Do not `views.open` or `views.push` again in the handler. No database and no `users.info` on that open. A handler that does not update shows the close-only denial. A failed open and `not_found` do not DM. `view_submission` `response_action` stays in `view_ack`.
- **Destructive confirms use a red in-modal button.** `submit_button_text=None` and `close_button_text="Cancel"`. The affirmative is a `danger` button in an actions block, routed as a block action (`confirm_*`, never a prefix of the opener, never `VIEW_MAPPER`). Slack's submit button cannot be styled. A checkbox on that modal is not an input block, because an input requires submit. Put it in an actions block, and on its action write the choice into `private_metadata` for the red button to read. Confirm copy code-ticks the Group, Workspace, and Channel names, the counts, and the day count. A modal that only explains something has Close and no second button that also dismisses.
- **Route through `routing.py`.** Do not add Bolt `@app.action` / `@app.event` — `app.py` already matches `.*` into `MAIN_MAPPER` / `VIEW_ACK_MAPPER`. A second decorator double-fires.
- **Clean Slack ID renames.** Rename the `action_id` / `callback_id`, the constant in `slack/actions.py`, the handler, and the `routing.py` entry together. Do not keep leftover Slack IDs mapped to the new handler. A stale Home tab may `no_handler` until Refresh; that is expected. Prefixed Home buttons (`join_sync_{id}`) must not share a prefix with a modal picker: `select_join_sync`, not `join_sync_select`. `create_sync` is not prefixed, so `create_sync_select` is fine. Two current buttons may share a handler (`decline_group_invite` / `cancel_group_invite`). Leftover env still warn-and-coalesce; old backup keys still import.
- **Modal field errors only in the ack phase.** `VIEW_ACK_MAPPER` may return `{"response_action": "errors", ...}` (3s budget, no Slack/DB of consequence). After ack, work-phase failures DM the user. A field error skips the work handler, in production and local development. Production runs the ack again in `main_response`, so an ack writes nothing that is unsafe to repeat.
- **`DbManager.get_record` uses each model's `get_id()` column, not always the integer PK.** Pass that value positional or as `id=` only (`team_id=` TypeErrors). `Workspace` → Slack `team_id`. `SyncChannel` → integer primary key. `PostMeta` → `post_id`. Objects are expunged; each call is its own session.
- **Soft-delete + no `ON DELETE CASCADE`.** Active queries need `deleted_at.is_(None)`. Hard deletes go through `purge_sync` / `purge_workspace` (children first, including soft-deleted rows). `purge_workspace` deletes settings and clears `source_workspace_id`, and returns False while an allowlist or pending stub row points at the workspace. The retention purge hard-deletes `deleted` rows past the window through `purge_sync_channels`, then the Sync, then a disbanded group with no Syncs left.
- **Imports are `import helpers`, not `from syncbot.helpers`.** Pytest `pythonpath` is `syncbot/` (and `infra/aws/lambda`). Do not add `tests` to it; import fixtures as `from tests.event_fixtures import …`.
- **Production runs a view ack twice.** `view_ack` answers Slack, then `main_response` runs the same ack handler again and skips the work if it returns errors. The second call cannot see the first answer, so an ack must not decide on state that can change between them, such as the run lock. Check that state in the work phase and DM the result.
- **Link buttons still need a no-op in `ACTION_MAPPER`.** Slack fires `block_actions` for URL buttons (`handle_authorize_syncbot` is the example); without a handler you get `no_handler` in the logs.
- **Never log tokens.** `redact_sensitive` (and request-body `_redact_sensitive`) must include `user_token` and `bot_token`. Do not print `xoxp` / `xoxb`, pairing codes, connection codes, group invite codes, or private keys.
- **Structured events use `log`.** Prefer `log_debug` / `log_info` / `log_warning` / `log_error` / `log_critical` (`from logger import log_debug`). Those wrap `log(event, level, **fields)` — *level* is required, there is no DEBUG default. Stable snake_case *event* is the log `message`. Decision points, not per-loop chatter. Do not add a second event helper. Filter `workspace_convert`, `federation_pair`, `migration_export`, `migration_import`, `teams_convert`, `push_teams`, `live_conflict`, `sync_channel_soft_deleted`, `sync_paused`, `sync_resumed`, and `member_joined_channel` for an export, import, or convert test. Filter `data_tools_`, `data_repair_`, `purge_`, and `run_lock_` for a Data Tools run.
- **Leave Sync** soft-deletes this workspace's `SyncChannel` (`status` `deleted`, `deleted_at`, retention) through `soft_delete_sync_channels`. It never purges. Create and Join of that Channel in the same Group call `rejoin_sync_channel` in `helpers/sync_lifecycle.py`: a Sync another member already revived wins, otherwise the newest removed row. Join revives only when that row's Sync is the one being joined. Pause writes `paused` and SyncBot leaves the Channel. A kick is the same pause, and a manager adding SyncBot back is Resume. Pause, Resume, Leave, uninstall, and Edit Sync invalidate every Channel in that Sync. `apply_target` re-reads the row so a stale cache cannot write to a paused or left Channel. The last publisher's Leave does not end the Sync: the other Channels stay, and the notice lists who is still in it. There are no sync owners.
- **Participation owns reaction direction.** Create Sync offers `publish_only` / `publish_and_subscribe`. Join Sync and Edit Sync offer those plus `subscribe_only`. Reaction UI chooses Hybrid, Direct, or Off. Off does not apply incoming add or remove. Do not revive leftover reaction-direction action IDs or radio fields.
- **Events API dedup is Slack envelope `event_id` + `team_id`** (`run_claimed`), not `event.ts` or `X-Slack-Retry-Num`. Sync fan-out uses one source-canonical envelope (`kind` + `action`) through `run_sync_pipeline`. Missing `event_id` always runs. Failed work releases the claim. Work that is not ready yet (`return False`) also releases the claim. Only one case is left: a file-share echo whose Channel Sync row is not visible yet (`complete_copy_ts_from_pending_share`). Deployed runtimes ack first, so Slack does not send it again. A reply, edit, delete, or reaction that arrives before its message's PostMeta is left pending instead (`leave_pending_event`, **Message loop**). Own-bot, pending-`file_share`, and unsynced subtypes complete the claim as no-ops so retries do not re-run them.
- **Publish/subscribe pipeline.** An origin must publish and a target must subscribe. Discover fan-out with `iter_publish_targets`; `get_sync_list` is gone and must not be reintroduced. Dedupe targets by workspace and channel. Same-instance (live on this install) uses `apply_target`; cross-instance (peer Channel) uses `deliver_remote`. Stub is the database row (`is_stub_workspace`), not a product name. A copy's inbound create never originates a second hop (echo + `copy_exists`). Reactions, thread replies, edits, and deletes on a publishing Channel still fan out on that message's `post_id` even when the row is a copy. Thread *creates* (and files in a thread) fan out locally only to Channels that already have the parent PostMeta. Trusted cross-instance Channels still get that envelope; inbound 409s if the peer has no parent. Edits, deletes, and reactions fan out to every publish target; local apply no-ops and inbound 409s when PostMeta is missing. Federation origin puts the target Channel's Slack ts on the envelope as `target_ts` when origin has that copy row. Inbound replies apply with that field, or with PostMeta on the resolved SyncChannel; edits, deletes, and reactions need that PostMeta row (`target_ts` alone is not enough). Outbound 409 `incomplete_file` restages parts once; `assemble_failed` does not upload again; `parent_missing` is a skip. A peer answers 200 with `ok: false` and `error` when its apply posted nothing, and `ok: true` with `error` for a reduced copy; `deliver_remote` collects them in `errors`. A 409 `parent_missing` on an edit, delete, or reaction is retried (the peer may still be applying the create), and when it is still missing the target is skipped, not reported. Do not key the peer on origin integer PKs. Do not put `thread_post_id` on reaction or edit envelopes. After you change `run_sync_pipeline`, `iter_publish_targets`, `apply_target`, `deliver_remote`, inbound federation apply, `run_claimed`, or the message/reaction handlers, retarget the **Message Sync Flow** `#L` links in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (and the mermaid if the hop changed).
- **Limits.** Use a documented Slack fact or a cap infra injects. Slack files are 1 GB. `conversations.history` and `conversations.replies` are Tier 3 (50+ per minute); pace a share-ts lookup at that rate and keep going until Slack returns the ts. - **Message loop / double-post.** Skip only SyncBot's own `bot_id`, not other bots. Ignore Slack `upload` (share-at-upload-time vs later, not new vs parent copy). `subtype=file_share` is a share. A plain **top-level** `message` with a downloadable hosted file is processed; wait for `file_share` only when those files have no private URL yet, or when Slack-hosted video/image blocks are present without one. A later same-ts `file_share` is `copy_exists`. Thread text replies (`thread_ts` ≠ `ts`, no `file_share`, has text) list the parent file and those files are stripped. Also-send-to-channel (`thread_broadcast` / `reply_broadcast`) keeps its files. A new file in a thread is `file_share`, or a file-only thread message (blank text, files present) when Slack omits the subtype. If the file cannot be copied, log `file_share_failed`; the author hears about it in the one message DM. The rest of the message still posts, with the copy note. When the files were the only content, that DM is sent and nothing posts; a later `file_share` may still bring them. A forward's own files (`get_share_files`) download only on a create, with the source bot token, then the forwarding user's token (`get_user_token`). A file neither reads joins the same DM. `thread_ts == ts` is the parent, not a reply. File-id echo skips kept-file events for the share we just wrote, not a later text reply that lists the parent file. Message-ts echo and copy PostMeta skip the inbound *create* of the copy. If complete-upload omits the share ts, keep reading channel history at Tier 3 until Slack returns it. The platform request timeout ends that lookup. If the upload returns without a ts, remember the in-flight apply (envelope post_id, sync_channel_id, source fields) keyed by Slack file id, and let the inbound own-bot or file-echo `file_share` commit that copy PostMeta. Do not DM a file-share failure when the file is already in Slack. A reply, edit, delete, or reaction looks up its message by ts (a reply, its parent). It can arrive while that message's create is still running, or before it (Slack's link-preview `message_changed` often does once it has the preview cached). Deployed runtimes ack before the work runs, so a released claim is not sent again: do not return `False` to wait for a message's PostMeta. Instead, after every gate and echo guard has passed, `leave_pending_event` remembers a `REPLAY` pending event (the source team, Channel, and ts, the action, and for a reaction the person, its name, and `event_ts`; a new reply waits on its parent through `source_thread_ts`, anything else on its own message) and looks once more. The create, right after it writes PostMeta, runs `_replay_pending_events`: it takes every `REPLAY` row waiting on that message (`take_pending_events_to_replay`), reads each message again from the synced Channel (`fetch_source_message`, once for every edit and delete of it), and sends it through `respond_to_message_event`, so every guard runs again: still there is an edit, gone is a delete, a reply is a new message, and a reaction runs `_sync_reaction_records` with its own `event_ts`. Each side writes before it checks, and each take is one atomic `DELETE` by id (`take_pending_event(REPLAY, id=…)`), so exactly one side applies the event. A Slack error while reading the message replays nothing. No sleeps and no runtime knowledge. Other bots' `bot_message` events are synced. User-token file shares look like the mapped person; echo and PostMeta must use the share ts, not the parent. A Slack token goes only to a URL that passes `is_slack_file_url`. An `is_outside_file` file is dropped before the file checks and comes back as its `external_url` link after enrich. It never downloads, waits, or DMs. A Slack file with no download URL and an `https` permalink (a canvas, `get_link_only_file_url`) comes back as that link through the same `add_outside_file_links`. A hosted file or snippet with no URL is a failed file, not a link.
- **Fail open inside the gates.** A message that passes every gate is copied even when part of it cannot be copied faithfully: Slack refusing blocks or attachments falls back to text, an unreadable file leaves the rest of the message, an unknown subtype is copied with a `message_degraded` warning (skipped with a `message_skip` warning when `hidden`), and a create with nothing readable posts its source permalink (`chat.getPermalink`) with a `message_degraded` warning. The gates never fail open: a Channel with no Sync, an origin that does not publish, a target that does not subscribe or is not `active` (paused, pending, removed, or uninstalled), a Workspace outside the Group, federation off or a peer that is not trusted or not allowed (`workspace_allowed_for_peer`), a private Channel when `allow_private_channels` is off, the Workspace Block List, and the own-bot and echo guards. A forward that landed in a publishing Channel is recreated for every subscribing target; the source Channel's privacy is not another gate. Same-instance and cross-instance share one envelope (`text`, `blocks`, `attachments`, `file_refs`). A reduced copy ends with `NOTE_COPY_DIFFERS` (`add_copy_note`: a `context` block when blocks carry the body, else an italic last line), and the author gets the one DM. `message_degraded` is the event to filter on for the next special case. The pipeline's setup skips (`stub_peer_unavailable`, `origin_not_allowed`, `workspace_not_deliverable`) log at info.
- **One DM per message that did not copy all the way.** After `run_sync_pipeline(…, report=[])`, the message handler's `_notify_author` sends the author one `format_error_dm`: each target that got nothing, each that got a reduced copy, causes found before fan-out (`ctx["degraded"]`), and an unreadable file, then "Please send this to a workspace admin so it can be fixed." Targets are `#name (Workspace)` in code ticks, or only the Workspace when `is_private` is not false. Write layers return errors and never DM: `slack_write_create` returns `(ts, posted_as, error)`, edit and delete `(ok, error)`, `ApplyOutcome.error`, and `deliver_remote(errors=…)`. A Slack code is final and is not retried; an error without one is raised so `_while_active` tries again. A gate is not a failure. Reactions and posts with no `user_id` only log `message_not_copied` or `message_degraded`.
- **A broken target Channel pauses.** `not_in_channel` and `channel_not_found` (`via="kick"`), `is_archived` (`archive`), and `restricted_action` (`restricted`) from a bot-token write pause that row in `apply_target` with `pause_sync_channel`, which tells that Workspace's managers once and replicates to peers. Managers never get a DM for a single message. `restricted_action` from a user token falls back to the bot first. Token errors are left to uninstall and revocation.
- **Old messages are not retried.** A reply, edit, or delete with no PostMeta whose ts (the parent's for a reply) is older than every publishing `SyncChannel.created_at` completes with `message_skip` / `before_sync` (`_is_before_sync`, `Decimal`). It writes no pending event. A newer one is left pending for its message's create (`leave_pending_event`).
- **File shares** are one native upload for both tokens. The file is the message. Plain text is `initial_comment` (or none when there is no text). Block Kit and a public GIF go on that upload as `blocks`. Attachments cannot go on an upload: a card's blocks follow the message's own blocks, and other attachments become a `section` of their words (`text_from_attachments`). `initial_comment` together with `blocks` drops the blocks. Bot posts set `username` and `icon_url` (`chat:write.customize`) on every file share, including file-only. User-token posts do not set those. The upload keeps reading the share ts at Tier 3 until Slack returns it. A source thread reply that was also sent to the channel then `chat.update`s `reply_broadcast`. Same-instance and cross-instance both do that in `apply_target`. Complete-upload does not accept that flag.
- **Block Kit is the message body.** Slack `event.text` is a notification fallback: it often strips newlines and truncates (the client "Show more" is chrome on `blocks`, not a second payload). Copy content blocks (`section`, `header`, `rich_text`, …), drop `actions`/`input`, rewrite mentions in place. Do not copy Slack-hosted `video`/`image` Block Kit URLs (`files.slack.com`) or `slack_file` images. The file goes through download and `file_refs`. When an image block shows a Slack file that is not in the event's `files`, `_build_file_context` reads it with `files.info` (`collect_slack_file_ids_from_blocks`). A Slack-file image inside a `section` or `context` is dropped, not copied. `table` is copied. A video from another site becomes a link, because Slack posts a video block only for the app that owns its domain. Image blocks keep only their input keys (`image_url`, `slack_file`, `alt_text`, `title`). Events add `image_bytes`, `image_width`, `is_animated`, and similar, and Slack refuses those on a post. When Slack refuses a copy's blocks or attachments (`_BLOCK_ERRORS`, including `invalid_attachments`), the create or edit posts the text once, with the attachments' words, and logs `slack_write_blocks_refused`. Attachments are copied as attachments (`build_attachments_for_sync`), on create and edit; an update always sends `attachments` (`[]` when none) and `text`, because Slack keeps what an update leaves out. A forward and a bare link to another message copy the same way: the author's words, the labeled link (`message in #channel (Workspace)`), then the card. A forward's `from_url` is appended with `append_link_lines` (text, and a `rich_text` link when blocks carry the body), so a peer that ignores attachments still gets the link. A pasted link's preview usually arrives on a `message_changed` a second later, and that edit adds the card; the source shows the same delay. A link the author wrote their own words for keeps those words and the source URL, and its preview is left out (`drop_previews_of_labeled_links`). The card is `color`, `fallback`, and `blocks` only: a `context` with the author icon, `author_subname` (else `author_name`) linked to `from_url`, and a `<!date>`; a `Posted in <#C…>` context; then the share's `blocks` (else `message_blocks`). Slack's own footer (`Slack Conversation`) and legacy fields are not sent. `@here` in a share is made plain. The source Channel's privacy is not another gate. Other attachments keep the documented legacy fields; `ts` is an integer. The envelope `text` is only what the author wrote. A refused card and mention lookup read the attachments' words with `text_from_attachments`. Image-only attachments stay on the `images` path. AI-app blocks (`card`, `carousel`, `container`, `layout`, `data_table`, `data_visualization`, `plan`, `task_card`) and other unlisted block types are dropped; the text fallback carries their words. A public image attachment (GIF picker) stays on the message when a hosted file is also attached. Do not prepend flattened `text` when those body blocks are present. Do not probe target emoji catalogs for message body emoji; that probe is reactions-only.
- **Live vs stub is `workspaces.instance_id`.** Uninstall, Leave Connection, and an allowlist drop soft-delete the workspace and write its rows `uninstalled` (PostMeta stays). Restore flips only `uninstalled` rows back. A `deleted` row stays deleted. Reinstall, import, or reclaim converts a stub back to local (`convert_workspace_to_local`). That restore calls `resume_restored_sync_channels`: public Channels pause with a notice, the bot joins, then they resume; private Channels stay paused with a notice. Reconnecting an External Connection restores that peer's stubs (`restore_peer_stubs`). Do not `purge_workspace` on Leave Connection.
- **Data Migration does not connect.** Import never creates, joins, or changes an External Connection. `get_migration_file_status` returns `unknown`, `not_connected`, `federation_off`, `connected`, `this_install`, `unchecked`, or `tampered`. `unknown`, `not_connected`, and `federation_off` import with a map of only the importing Workspace, call `restore_migrated_workspace` directly, send no `/teams` push, and never create `instances` rows or stubs. `this_install` and `connected` keep the peer check. Check `is_self_instance` before a trusted peer. A changed file is refused. `unchecked` imports like `unknown` (this Workspace only) only while `unsigned_import_enabled()` is true, after Confirm Import warns that the file was not checked. Off, it is refused. `tampered` is refused. Export writes `source_instance` with only `instance_id` and `public_key`. The source's name comes from the `instances` row (`name`, else `Connection` and the id prefix), never the file. `helpers/export_import.py` does not `import helpers`; `federation_enabled` comes from `helpers.settings`. Import writes rows only for the importing Workspace and the stubs that signer allows, joins an existing Group only when that Workspace is an active member, keeps an existing Sync in its Group, and starts a new Group with only that Workspace. A standalone kind (`unknown`, `not_connected`, `federation_off`, `unchecked`) keeps the Workspace's role in a Group that already exists here (`keep_existing_roles`); the file sets a role only on a Group the import creates. `_run_migration_import` runs `import_migration_data` in one `transaction()`, and directory rows are checked before the directory is replaced, so a bad file changes nothing. A blank team id is the importing Workspace for a Channel row, and a mapping needs both team ids. An `active` Channel stays `active`. A `connected` or `this_install` import asks every trusted peer before `pending` Channels resume, with this team appended to the `/teams` payload. A peer that cannot be reached, or that refuses the check, keeps those Channels waiting, and the DM says what to do.
- **In-process cache is per warm container (60s).** Writes that change fan-out or Home must invalidate the relevant participation/settings keys, the `home_tab_hash:` prefix, and `fed_ws_for_sync:` after federation pair/unpair/restore. Pause/Leave/uninstall must invalidate **every** Channel in the sync, not only this workspace's Channel — `publish_targets:{origin}` is keyed by the publisher.

Do not emit target `<#C>`, `slack://`, `app.slack.com/client`, or channel-only `archives/C` URLs. Home may still use native `<#C>` for **this** workspace's own channel. Rich_text `{type: channel}` becomes a `text` element with `style.code`.

- **Scope lockstep.** `slack_manifest_scopes.py` + `slack-manifest.json` / `_test` / `_prod` + SAM/Terraform defaults + env examples. User scopes that do not match the Slack app fail install with `invalid_scope`.

Backup/reset also need the matching team; reset also needs `ENABLE_DB_RESET`. Do not add that workspace to a group or make it a group owner for being primary.
- **Repair and migration 022 share the rules in `helpers/data_repair.py`.** A change to one changes the other. A Channel belongs to its Sync's Group. Repair commits once (`transaction()`); a failure rolls the database back. Every `DbManager` call, `read_session`, and `write_session` joins an open `transaction()`. Duplicate Channels keep an `active` row ahead of `paused`, then `pending`, then the oldest. Message records and other large tables change in batches of 500. A blank foreign key is not a missing row.
- **Instance-wide writers share one run lock** (`db/run_lock.py`, `DATA_MAINTENANCE`): Data Tools, the retention purge, Restore, Reset Database, and Data Migration import. It is an `instance_settings` row keyed `lock:…`, so every process sees it; the in-process cache does not. Use `hold_lock`; it refreshes the row while the work runs and releases it after. Take it outside `transaction()` (it raises inside one). Only the token that took it releases it, and a row older than its TTL is taken over. Backup and restore skip `lock:` rows. Take the lock in the caller, not in `purge_soft_deletes`, or a Data Tools Purge would wait on itself. Busy copy is `_MAINTENANCE_BUSY_TEXT`. `purge_stale_soft_deletes` never raises. A new instance-wide writer takes this lock too.

Every parent delete removes children first. Repair, migration 022, and the purge never write `instances` or `federation_*` tables.
- **`post_message` sends `syncbot_post` metadata** with the `post_id` on new posts. Keep it when changing how copies are posted.
- **Group succession is purge-only.** Uninstall keeps the group; Home shows remaining members with no owner until retention ends. After the retention window, promote the earliest-joined remaining member (this instance or another) or disband. Home does not promote on read. Leave requires another active owner; a sole member sees Disband Group, not Leave Group. `PRIMARY_WORKSPACE` may join or be invited; it is never auto-added or made owner for being primary. The picker offers a stub only when the inviting Workspace is shared with that stub's instance (`workspace_allowed_for_peer`). With no row, it writes a `pending` row and calls `send_group_invite_dm`. An active or pending row stays. Decline and Cancel of an invite that crossed instances send `/group-leave`, and a leave for a `pending` row deletes it and rewrites its DMs. Join by code replicates like Accept. Canonical GitHub bot identity is App **`f3n-community-automation`** (see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)); forks do not install it.
- **User scopes on Home** — do not paste Slack API names (`groups:write`) onto **Authorize SyncBot**. The comment on that constant is the labeling recipe: Slack scopes docs → 2–4 ordinary words, fold read/write twins, keep `groups:write` separate. - **OAuth starts at `/slack/install`.** Never link at `slack.com/oauth/v2/authorize`. The federation instance id is a SHA-256 fingerprint of the Ed25519 public key. Inbound file-part and JSON size are this hop's injected `FEDERATION_HTTP_MAX_MB` in [docs/INFRA_CONTRACT.md](docs/INFRA_CONTRACT.md) (`file_chunk_mb` / `json_chunk_mb`; `0` means this hop did not inject a cap). Slack files stay 1 GB. The sender splits to the peer's advertised cap; `0` or omitted is one part, never a guessed MiB default. A 413 retries only when the peer advertises a smaller positive cap. Do not detect `K_SERVICE` or `AWS_LAMBDA_FUNCTION_NAME` for this. Tests assert behavior given a cap. Do not slice mentions or `files[:20]`. Remap every `<@U…>`. Page `/users` on the existing path. Do not add leftover names back as required env vars.

## Message variants

Every shape SyncBot has met in a synced Channel, and what the copy shows. Add a row when you find a new one. A shape that passes the gates but cannot be copied faithfully still posts (see **Fail open inside the gates**) and logs `message_degraded`.

| What the source shows | What Slack sends | What the copy shows |
| --- | --- | --- |
| A typed message | No subtype. `rich_text` blocks plus a `text` fallback | The blocks, with mentions mapped and `#channel` code-ticked |
| `/me` message | `me_message` | The same as a typed message |
| App post with Block Kit | `bot_message`, or a `bot_id`. Blocks are sometimes missing from the event | Content blocks. Missing blocks are read with `conversations.replies` |
| App image in Block Kit | An `image` block with `image_url` plus `image_bytes`, `image_width`, `is_animated`, and similar | The image block with only its input keys |
| App or webhook post with attachments | `attachments` with `pretext`, `title`, `text`, `fields`, `footer`, `color`, sometimes `blocks`. `text` may be blank or a short fallback | The text, plus each attachment with its documented fields and an integer `ts` |
| Forwarded message | No subtype. Blank `text` and no blocks unless there is a comment. One attachment with `is_share` and `is_msg_unfurl`, the original Block Kit as `blocks` (older payloads: `message_blocks`), a string `ts`, `author_subname` for the shown name, `channel_id`, `from_url`, and the footer `Slack Conversation` | The comment, the `message in #channel (Workspace)` link to the source, then a grey-bar card: the author's icon and name linked to the source message, the date, `Posted in` and the code-ticked source Channel, and the original blocks without buttons. On every subscribing target, whatever the source Channel's privacy |
| Forwarded app post | The same, with `author_name` the app and `author_subname` `Name (via App)` | The same card, named `Name (via App)` |
| Forwarded message with files | The share attachment carries `files` | Uploaded with the copy when the source bot token or the forwarding user's token can read them. An upload cannot carry attachments, so the card's blocks go on the upload, without the grey bar. A file neither token reads is in the author's DM, and the card still posts |
| Forward of a thread reply | The share also sets `is_reply_unfurl` or `is_thread_root_unfurl` | The same as a forward |
| Forward from a DM | The share's `channel_id` is a `D…` id | The same card with no `Posted in` line |
| Pasted message link | A `message_mention` in the blocks. The preview (`is_msg_unfurl`, `original_url`, `from_url`, no `is_share`) arrives on a `message_changed`, a second later, or before the create when Slack has the preview cached | The same as a forward: the words, the `message in #channel (Workspace)` link with the source URL, then the card. The edit adds the card. When it comes first, it is left pending and the create replays it (`leave_pending_event`) |
| Link to a message with the author's own words | `<url\|words>` in the text, a `link` element with that `text`, and the same preview | The link with the author's words and the source URL. No card |
| Pasted website link | The URL in the text. The preview attachment (`original_url`, `service_name`, `title`, `thumb_url`) often arrives later on `message_changed` | The link, plus the preview card with `service_name` as its author. Slack does not unfurl the copy again (`unfurl_links=false`) |
| App link preview | An attachment with `is_app_unfurl` and `blocks` | The preview card with its blocks |
| GIF picker or Giphy | An attachment or block with only a public `image_url` | An image block |
| Uploaded file, image, snippet, or clip | `file_share`, or a top-level message whose files already have `url_private` | The file uploaded to the target, with the text as the comment or as blocks |
| File from Google Drive and similar | A file with `is_external` or `mode: external` | A link to its `external_url` |
| Canvas | `file_share` with a `quip` file that has a `permalink` and no download URL | A link to the canvas |
| File hidden by the Free plan limit, deleted, or unreadable | `hidden_by_limit`, `tombstone`, `file_access`, or a download that fails | The rest of the message, with the copy note. The author gets the one DM. When the files were the only content, only the DM |
| Image or video stored in Slack, shown in a block | An `image` or `video` block with a `files.slack.com` URL or `slack_file` | The file is read with `files.info` and uploaded |
| Video from another site | A `video` block | A link |
| Table | A `table` block | The table. When Slack refuses it, the text |
| Buttons, menus, and inputs | `actions`, `input`, or an interactive accessory | Dropped. They would be dead controls. The section text stays |
| App-only or unlisted block types | A block type SyncBot does not list | Dropped. The text fallback carries the words |
| Blocks or attachments Slack refuses on the target | `invalid_blocks`, `invalid_attachments`, and similar | The text, with the attachments' words and the copy note. The author gets the one DM |
| A copy Slack or a peer refused | A Slack error code on the target, or a peer's `ok: false` | Nothing on that target. The author's DM names it with the code |
| A target Channel SyncBot cannot post in | `not_in_channel`, `channel_not_found`, `is_archived`, or `restricted_action` from the bot | That row pauses, and its Workspace's managers are told once. Later messages skip it until it resumes |
| Nothing SyncBot can read | Nothing usable in text, blocks, attachments, or files | The labeled source permalink and the copy note, with a `message_degraded` warning. The author gets the one DM |
| Thread reply | `thread_ts` not equal to `ts` | A reply under the parent's copy |
| Reply also sent to the Channel | `thread_broadcast` | A reply under the parent's copy, also sent to the Channel |
| Edit | `message_changed`, with the new message on `event.message` | The copy is edited, attachments and cards included. A removed preview is removed |
| Delete | `message_deleted` | The copy is deleted |
| `@here`, `@channel`, or `@everyone` typed by the author | `<!here>` and similar, or a `broadcast` element | The same ping on the target |
| `@here` and similar inside a forward or preview | The same, inside the attachment | Plain `@here` text. It does not ping |
| `#channel` mention | `<#C…>`, or a `channel` element | `` `#name (Workspace)` `` in code ticks. Never the target twin |
| SyncBot's own post | SyncBot's `bot_id`, or an echo of a user-token post | Skipped |
| Another app's post | Another `bot_id` | Copied |
| Joins, leaves, topic, purpose, name, pins, integrations added or removed, and similar | The system subtypes in `handlers/message.py` (`_SYSTEM_SUBTYPES`) | Skipped |
| Archive, unarchive, privacy change | `channel_archive` and similar | The Sync pauses, resumes, or ends for that Channel |
| A subtype SyncBot does not know | Any other subtype | Copied with the copy note and a `message_degraded` warning; the author gets the one DM. Skipped with a `message_skip` warning when the event is `hidden` |
| Reply, edit, or delete of a message from before the Sync | No PostMeta, and a ts older than the Sync | Nothing. Not retried |
| A Channel or Workspace a gate stops | No Sync, not publishing, not subscribing, not `active`, not in the Group, peer not trusted or allowed, private Channels off, Block List | Not copied. Gates never fail open |
| Slack Connect, Enterprise Grid, Lists | Not Free features | Not handled |
